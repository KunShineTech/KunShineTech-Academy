## 1. 厨房里的万能机器：函数是什么
三级时我们写程序，所有代码都挤在 main 里，像一个厨房里什么东西都堆在灶台上。其实 C++ 允许我们造**一台台专用机器**：放进原料，按下按钮，出来成品。这台机器就是**函数**。

库里的 `sqrt`、`max` 都是现成的机器；模块化编程的思想就是：**把大问题拆成小任务，每个任务交给一台机器（函数）去做**，main 只负责指挥。

## 2. 函数的定义与调用
定义一台机器要写清四件事：**返回类型、名字、参数、加工过程**。

```cpp
int add(int x, int y) {   // 返回类型 int，名字 add，参数 x、y
    return x + y;         // 加工：把结果递出来
}

int main() {
    int s = add(3, 5);    // 调用：放原料 3 和 5，接住成品
    cout << s << '\n';    // 8
    cout << add(10, 20) << '\n';  // 调用也可以直接塞进 cout
}
```

三条铁律：
1. `return` 把结果递出函数，函数**立即结束**。
2. 返回类型写 `void` 表示「这台机器只办事，不出成品」，如 `void hello() { cout << "hi"; }`。
3. 调用函数前，编译器必须已经见过它的声明或定义——就像下单前得先知道店里有这台机器。

## 3. 函数的声明：先立一张字据
有时函数太长，想把定义写在 main 的后面，那就在前面**先立字据（声明）**，告诉编译器「有这么一台机器，别慌」：

```cpp
int add(int x, int y);    // 声明：只写头部，以分号结尾

int main() {
    cout << add(3, 5) << '\n';
}

int add(int x, int y) {   // 定义：写完整函数体
    return x + y;
}
```

声明 = 函数头 + 分号，**没有函数体**；定义 = 函数头 + 函数体。声明里参数名可以省略（`int add(int, int);`），但类型不能省。

> 教学提醒：函数要先声明（或定义）再调用。把函数定义写在 main 后面时忘记在前面加声明，是最经典的编译错误之一，报错类似「add was not declared in this scope」。

## 4. 形参与实参：菜谱上的名字 vs 真实的原料
```cpp
int add(int x, int y) { return x + y; }   // x、y 是形参
int s = add(3, 5);                        // 3、5 是实参
```

**形参（形式参数）**是函数定义时占的「空位」，像菜谱上写的「鸡蛋两枚」；**实参（实际参数）**是调用时真正放进去的值，像厨房里拿出的真鸡蛋。调用那一刻，实参的值被一一对应地装进形参的空位。
