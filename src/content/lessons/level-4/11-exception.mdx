## 1. 程序也会「受伤」：认识异常
跑步崴了脚，你不会当场倒下装死，而是喊一声「我受伤了」，让医护来处理。**异常（exception）**就是程序运行时出现的意外情况：除以 0、数组越界、文件打不开……以往这些情况轻则输出乱值，重则程序直接崩溃黑屏。

异常处理机制让我们可以**主动布下哨兵**：预测可能出事的地段，一旦出事就抛出信号、转入专门的应急通道，让程序体面地报告错误，而不是原地爆炸。

## 2. 三兄弟：try、throw、catch
- **try**：圈出「可能出事」的代码块，像给路段围上警戒线圈。
- **throw**：发现情况不对，**抛出**一个异常信号（可以抛 int、字符串、double 等任何值）。
- **catch**：在路口接应，**捕获**对应类型的信号并处理。

```cpp
try {
    if (b == 0) throw "除数不能为 0";   // 抛出 const char* 类型信号
    cout << a / b << '\n';
} catch (const char* msg) {              // 接住同类型的信号
    cout << "发生错误：" << msg << '\n';
}
```

口诀：**「try 圈地，throw 报警，catch 善后」**。流程是：try 里抛出异常后，**立即跳出 try 块**，匹配第一个类型相符的 catch 执行；如果没有任何 catch 接得住，程序仍会以异常终止。

## 3. 完整示例：除零保护
```cpp
#include <iostream>
using namespace std;
int main() {
    int a, b;
    cin >> a >> b;
    try {
        if (b == 0) throw -1;        // 用 int 当信号
        cout << a / b << '\n';
    } catch (int e) {                // int 信号由这里接住
        cout << "Error: 除数为零（代码 " << e << "）\n";
    }
    cout << "程序正常结束\n";        // 处理后继续往下走
}
```

输入 10 0，输出 Error 提示后继续打印「程序正常结束」——程序没有崩溃，优雅地处理了意外。也可以写 `catch (...)` 表示「任何类型的异常我都接」，作为兜底的应急通道。

> 教学提醒：throw 抛出值的类型要和 catch 参数类型匹配，匹配不上会漏接；漏接且没有 catch (...) 时程序会异常终止。教学中先让学生统一用 int 或字符串当信号，减少匹配混乱。

## 4. 异常处理 vs 返回值判断
「让函数返回 -1 表示出错」是老办法，但调用者可能忘记检查返回值；异常机制强制你必须应对（不接住就崩），错误不会被悄悄吞掉。不过也别滥用：**可预期的普通分支（如成绩不及格）用 if 就够，只有真正的「意外」才抛异常**。
