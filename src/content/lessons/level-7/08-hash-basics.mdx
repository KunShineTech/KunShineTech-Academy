## 1. 查字典的启发：地址 = f(内容)
为什么数组查找这么快？`a[2024]` 一步定位——因为**下标本身就是地址**。那如果我想查「学号 20241379 的同学坐在哪」，而学号和座位号没有直接关系呢？

**哈希（hash）** 的想法特别聪明：给内容算一个函数值，把它当地址用。像快递公司分拣：包裹上的手机号决定了它进哪个格口，不用一件一件翻。这个函数叫**哈希函数**，算出来的位置叫**哈希地址**。

最理想的情况：查询、插入、删除都是 **O(1)**——和数组下标一样快，却不受「下标必须是整数」的限制。

## 2. 哈希函数与取模
最简单的哈希函数是取模：**h(x) = x mod p**，把任意整数压到 0~p-1 的范围。p 通常取**质数**（比如 100003、1000003），能让数据分布得更均匀，减少扎堆。

```cpp
int h(int x) { return x % 100003; }
```

但要注意：哈希表装得**越满，冲突越频繁**。一般用「元素个数 ÷ 表长」即**装填因子**衡量拥挤程度，超过 0.7 就该扩容了。

## 3. 冲突：两个包裹进同一个格口
学生多了，总有两个人算出同一个座位号——这就是**冲突（碰撞）**。哈希表里冲突**不可避免**，只能优雅地处理。两大流派：

**流派一：拉链法。** 每个格子不存一个元素，而是挂一条小链子（链表）。同座位的同学排成一队，查的时候先定位再顺链找。

```cpp
const int P = 100003;
vector<int> table[P];            // 每条链存哈希值相同的元素

void insert(int x) {
    table[h(x)].push_back(x);    // 直接挂到对应链尾
}
bool find(int x) {
    for (int y : table[h(x)])
        if (y == x) return true; // 链上逐个比对
    return false;
}
```

**流派二：开放寻址（线性探测）。** 座位被占了？往下一个座位看看，再占就再往下，直到找到空位。查找也沿同样的路线走。

> 教学提醒：竞赛中最常用的其实是「偷懒版哈希」——值域不大就直接开大数组当下标用（如 cnt[x]++）；值域太大（如 10⁹）才需要真正的哈希或排序。先想清楚值域，再决定武器。

## 4. 查找的完整流程
用拉链法查找元素 x，分两步走：

1. **定位**：算 h(x)，一步跳到对应桶；
2. **比对**：沿桶里的链逐个与 x 比较，找到返回 true，走完没有返回 false。

这两步合起来平均 O(1)，最坏（所有人都冲突成一条链）退化成 O(n)——所以哈希函数的质量和装填因子决定了哈希表的真实速度。
