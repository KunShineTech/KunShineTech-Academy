## 1. 电报员的烦恼：为什么要编码压缩
假如要给「ABACAB」发电报，每个字符用 8 位二进制（ASCII）要 48 位。电报员发现：这段话里 A 出现 3 次，B 出现 2 次，C 出现 1 次——**用得越多的字母，越应该用短的编码**，就像常见字用简写（「你好」打成「泥嚎」也看得懂）。

但随便缩短会出乱子：若 A 编码为 0，B 为 1，C 为 00，收到 00 到底是一个 C 还是两个 A？解决办法是**前缀码**：任何字符的编码都不是另一个字符编码的前缀。树形编码天然满足这一点——**只有叶子才分配编码，走到叶子就停**，不可能有「某编码是另一个前缀」的情况。

## 2. 哈夫曼编码：建一棵编码树
用上节课的哈夫曼树，规定**向左走记 0、向右走记 1**，从根走到叶子的 01 序列就是该字符的编码：

以频率 A=3、B=2、C=1 为例：先合并最小的 B? 不，先合并 C(1) 和 B(2) 得 3，再与 A(3) 合并得 6。设 C 在左、B 在右：C=00，B=01，A=1。

三个要点：
1. **构造方法**：和第 3 课完全一样——每次取两个最小合并，只是这次把每个叶子标上字符。
2. **总长度**：编码总长度 = **哈夫曼树的 WPL** = 各字符频率 × 编码长度之和 = 每次合并产生的新权值之和。上例 = 1×2 + 2×2 + 3×1 = 9 位（原 ASCII 要 24 位，省了一半多）。
3. **解码**：从根出发，读到 0 往左、读到 1 往右，**一走到叶子就输出字符并跳回根**，继续读下一位。

> 教学提醒：哈夫曼编码不唯一——左右子树互换（0/1 互换）或相同权值的合并顺序不同都会得到不同的编码表，但**总长度（WPL）一定相同且最短**。考试问「哪个编码是哈夫曼编码」时，抓住两点：是前缀码，且总长度最短。

## 3. 格雷编码：只差一步的邻居
转盘锁、卡诺图、旋转编码器都用得到**格雷编码（Gray Code）**：把 0~2ⁿ-1 排成一个环，**相邻两个数的编码只有一位不同**。普通二进制从 1（01）变 2（10）时两位同时跳，机械触点可能瞬间读到 00 或 11 出错；格雷编码每次只变一位，稳。

两位格雷码：`00 01 11 10`；三位：`000 001 011 010 110 111 101 100`。**口诀：高位抄下来，其余每位 = 二进制该位与上一位的异或**。

计算公式（记这一个就够）：
```
G = n ^ (n >> 1)      // 二进制 n 转成格雷码
```
右移一位再异或，正好把「相邻只变一位」安排得明明白白。反推公式也有：`n` 的每一位 = 格雷码从高位到当前位的连续异或，六级掌握正向转换即可。

```cpp
int gray = n ^ (n >> 1);   // 十进制 n 的格雷码值
```

<Reveal label="查看参考程序与思路"><pre><code>{`#include <iostream>\n#include <queue>\nusing namespace std;\nint main(){\n    int n; cin>>n;\n    priority_queue<int, vector<int>, greater<int> > pq;\n    for(int i=1;i<=n;i++){ int x; cin>>x; pq.push(x); }\n    long long ans = 0;\n    while(pq.size() > 1){\n        int a = pq.top(); pq.pop();\n        int b = pq.top(); pq.pop();\n        ans += a + b;\n        pq.push(a + b);\n    }\n    cout<<ans<<'\\n';\n}`}</code></pre>priority_queue 默认是大顶堆，加上 greater&lt;int&gt; 变成小顶堆。每次取两个最小合并，把新权值累加到答案并放回堆中。循环结束时累加的总和就是 WPL，即最短编码总长度。样例：1+2=3，3+3=6，答案 3+6=9。</Reveal>
