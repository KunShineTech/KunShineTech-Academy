## 1. 解剖第一个程序
写程序像写一封写给计算机的信：信有固定格式，计算机收到后照做。请看这个经典程序：

```cpp
#include <iostream>   // 引入输入输出工具箱
using namespace std;  // 使用标准命名空间
int main() {          // 程序从这里开始执行
    cout << "Hello, world!" << '\n';  // 在屏幕上输出一行文字
    return 0;         // 向操作系统报告：一切正常
}
```

逐行解读：

- `#include <iostream>`：请工具箱进场，没有它就不能用 `cout` 和 `cin`。
- `using namespace std;`：告诉编译器名字可以省略前缀，初学阶段照写即可。
- `int main() { ... }`：`main` 是程序的入口，程序从这里开始、到这里结束。
- `cout << "..."`：`cout` 负责向屏幕输出，`<<` 像一根传送带，把内容送出去。
- `return 0;`：返回 0 表示程序正常结束。

## 2. 从源代码到可执行文件
计算机只认识机器语言（一长串 0 和 1），不认识英文。于是需要一位“翻译官”——**编译器**：

1. 我们写出**源代码**（`.cpp` 文件，人能读懂）。
2. 按 F9 **编译**：编译器检查语法，翻译成机器指令。
3. **链接**：把程序和需要的库拼接起来。
4. 生成**可执行文件**（Windows 上是 `.exe`），双击就能运行。

翻译不通时，编译器会在信息区列出错误位置和原因，就像老师批改作文：先看第一处错误，改完再编译，直到全部通过。

## 3. 注释：写给人看的便签
**注释**是程序里的说明文字，编译器会忽略它，它只帮助人读懂代码。

```cpp
// 这是单行注释：从两个斜杠到行尾都无效

/*
   这是块注释：
   可以横跨多行
*/
```

好习惯：在关键步骤前写一句「为什么这样做」，三个月后回头看也能秒懂。

> 教学提醒：注释不能用中文全角符号开头混淆，符号要用英文半角 `//`；注释里写错内容不会报错，但会误导阅读者。

## 4. 例题解析
**问题**：如果删掉 `return 0;`，程序还能运行吗？

**思路**：能。`main` 函数执行到右大括号时会自动返回 0。但建议养成写上的习惯，让「正常结束」一目了然。

## 5. 课后巩固
1. 默写第一个程序的完整代码，并给每一行加上注释。
2. 向同学解释：源文件和可执行文件分别给谁看？
3. 故意删掉一个分号，按 F9 观察编译器报什么错，再改回来。
4. 挑战：用一条 `cout` 和多个 `<<` 输出两行文字（提示：`'\n'` 可以夹在传送带中间）。
