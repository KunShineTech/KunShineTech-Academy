## 1. 贪心：每一步都「赚眼前的便宜」
超市找零：要找你 37 元，你会先给一张 20、再一张 10、一张 5、两张 1——**每次都给不超过剩余金额的最大面额**。你没试过所有给法，却坚信这样张数最少。**贪心算法**就是这种策略：面对多步决策，每一步都选当前看起来最好的选择，希望拼出全局最优。

贪心代码通常短小高效（常配合排序 O(n log n)），但它有个「脾气」：**不是每个问题都适用**。用错地方，步步「最优」拼出全局最差。所以用贪心前必须回答：这道题凭什么可以贪心？

## 2. 最优子结构：贪心的「许可证」
**最优子结构**：一个问题的最优解，能由子问题的最优解组合而成。找零问题里，「37 元的最优找法」=「先拿一张 20」+「17 元的最优找法」——子问题独立且最优，贪心才有效。

判定经验（课本级经典结论，可直接用）：
- 活动安排/区间选点：按**结束时间早**的先选，正确。
- 找零（面额成倍数体系，如 1、5、10、20）：贪心正确。
- 一般性找零（面额如 1、3、4，要凑 6）：贪心会错！2 张 3 元才是对的，贪心给 4+1+1。

**口诀：每步取眼前最优，全局未必最优；先证最优子结构，再让贪心上场。**

> 教学提醒：一定要让学生见一次贪心的「翻车现场」（1、3、4 凑 6），破除「贪心万能」的错觉。会证不敢证先另说，至少养成「先质疑、后使用」的习惯。

## 3. 经典例题：活动安排
有 n 个活动，每个有开始时间 s 和结束时间 e，同一时间只能参加一个，最多能参加几个？

贪心策略：**按结束时间从小到大排序，依次选「与已选不冲突」的活动**。

```cpp
sort(a, a + n, [](Activity x, Activity y) { return x.e < y.e; });
int cnt = 0, last = -1;                 // last 记录上一个选中活动的结束时间
for (int i = 0; i < n; i++)
    if (a[i].s >= last) { cnt++; last = a[i].e; }
```

直觉：结束越早，给后面留下的空档越多——「早结束的让路快」。这正是可证明的最优子结构：第一个活动一定存在一种最优方案选了结束最早的那个。

## 4. 贪心与枚举、二分的分工
遇到「最多/最少/最大/最小」的优化题，三步思考：
1. 能枚举答案并逐个 check 吗？（小规模可以）
2. 答案满足单调性吗？满足则**二分答案**（上一课）。
3. 每步决策有明确的「局部最优」且可论证全局最优吗？用**贪心**，通常是三者中最快的。

贪心常与**排序**搭档：先排序把「好选择」排到一起，再线性扫一遍做决策，整体 O(n log n)。

## 6. 课后巩固
1. 概念题：用自己的话解释「最优子结构」，并举一个具有它、一个不具有它的例子。
2. 编程题：读 n 个数，规定从小到大依次取数，第 k 个被取的数得分为「数 × k」。按此规则求总得分（直接从小到大排序后加权求和即可——体会「排序 + 线性处理」的贪心结构）。
3. 编程题： implement 找零（面额 1、5、10、20、50、100），输入金额，输出最少张数及每种面额张数。
4. 思考题：「会议室预约」和活动安排是同一个问题吗？如果每个活动还有权重，要求总权重最大，贪心还行吗？
5. 拓展：查阅「Huffman 编码」，说说它为什么也是贪心思想。
