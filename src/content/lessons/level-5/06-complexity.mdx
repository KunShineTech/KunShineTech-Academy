## 1. 为什么算法要「计时」？
同样算 1~n 的和，电脑用 0.001 秒，你呢？比赛中评测机每秒约执行 10⁸ 条基本语句。如果 n = 10⁹，一个需要循环 n 次的程序要跑 10 秒——**超时（TLE）**，得零分。所以我们不关心程序「跑多快」，而关心**操作次数随 n 增长的速度**，这就是**时间复杂度**。它像汽车的油耗指标：不告诉你具体花多少钱，但告诉你这车费不费钱。

## 2. 大 O 记号：只看增长趋势
大 O 记号描述「n 很大时」的量级，两个规矩：
1. **扔掉常数**：O(2n) 记作 O(n)，O(500) 记作 O(1)。
2. **只留增长最快的项**：O(n² + n) 记作 O(n²)，因为 n 很大时 n 相对 n² 微不足道。

常见复杂度「食物链」（从快到慢）：

**O(1) < O(log n) < O(√n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) < O(n!)**

> 教学提醒：强调复杂度是「n 很大时」的趋势。n=10 时 O(n²) 可能比 O(n log n) 还快，但 n=10⁵ 时前者要 10¹⁰ 次运算必超时，后者约 10⁶·17 次绰绰有余——估算的对象永远是大数据。

## 3. 读代码估复杂度：数循环
单重循环跑 n 次 → O(n)；双重循环各跑 n 次 → O(n²)。几个判断技巧：

```cpp
for (int i = 1; i <= n; i *= 2)    // i: 1,2,4,8,... 翻倍到 n → O(log n)
for (int i = 1; i * i <= n; i++)   // i 到 √n → O(√n)
```

判断「i *= 2」这类倍增循环：问自己要乘多少次 2 才能到 n？答：log₂n 次。**口诀：每轮减半/翻倍是对数，每轮 ±1 是线性。**

## 4. 对数：算法世界里的「对折魔法」
一张纸对折一次变 2 层，对折 10 次是 1024 层，对折多少次能超过 10⁹（十亿）层？只要 **30 次**！log₂10⁹ ≈ 30。这就是对数复杂度恐怖的地方：**数据翻 1000 倍，步骤只多 10 步**。二分查找（下一课）正是靠每次砍一半实现 O(log n)。记住这张对照表：

| n | O(n) | O(n log n) | O(n²) |
|---|------|-----------|-------|
| 10⁴ | 10⁴ | 约 13×10⁴ | 10⁸（临界） |
| 10⁵ | 10⁵ | 约 17×10⁵ | 10¹⁰（必超时） |

<Reveal label="查看参考程序与思路"><pre><code>{`#include <iostream>\nusing namespace std;\nint main(){\n    int n; cin>>n;\n    long long odd = 0, even = 0;\n    for(int i=0;i<n;i++){\n        long long x; cin>>x;\n        if((x%2+2)%2==1) odd++; else even++;\n    }\n    cout<<odd*(odd-1)/2 + even*(even-1)/2<<'\\n';\n}`}</code></pre>两重循环要约 5×10⁹ 次运算必超时。突破口是第一课的奇偶性：和为偶数当且仅当两数同奇偶，所以答案 = 从 odd 个奇数中任选 2 个 + 从 even 个偶数中任选 2 个 = C(odd,2)+C(even,2)。一趟 O(n) 统计就搞定。样例中奇数 `{1,3}`、偶数 `{2,4}`，各贡献 1 对，共 2 对。负数取余要先加 2 再取模保证非负。这就是复杂度分析的价值：它逼你找到更聪明的办法。</Reveal>

## 6. 课后巩固
1. 概念题：说明为什么 O(n² + 100n) 要写成 O(n²)，常数 100 和项 100n 为什么可以丢。
2. 计算题：估算下列循环的复杂度——`for(i=1;i<=n;i++) for(j=1;j<=i;j++) sum+=i*j;`（提示：内层次数是 1,2,…,n。）
3. 编程题：读 n（n≤10⁹），输出 1~n 的和。要求不超时，说明你程序的复杂度。
4. 思考题：O(n log n) 的排序算法处理 n=10⁶ 的数据大约要多少量级运算？为什么远好于 O(n²)？
5. 拓展：查一查「P 与 NP」，用自己的话写三句话介绍这个著名问题。
