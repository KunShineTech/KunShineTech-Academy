## 1. 猜数字游戏
心里想一个 1~100 的数，让别人猜。笨办法从 1 猜到 100，最多 100 次；聪明办法先猜 50——「大了」就丢掉上半段，「小了」就丢掉下半段，每猜一次**范围砍半**，最多 7 次必中！这就是**二分查找**：在**有序**序列里，每次用中间元素和 target 比较，排除一半。

## 2. 二分查找模板
```cpp
int l = 0, r = n - 1;              // 在 a[0..n-1] 里找 target
while (l <= r) {
    int mid = (l + r) / 2;
    if (a[mid] == target) { /* 找到，break 或返回 */ }
    else if (a[mid] < target) l = mid + 1;  // 目标在右半
    else r = mid - 1;                        // 目标在左半
}
```

**三条铁律**：
1. 前提是有序（升序/降序均可，比较方向反过来即可）。
2. `mid = (l+r)/2`，l、r 很大时写作 `l + (r-l)/2` 防溢出。
3. 每次排除必须「不含 mid」：`l = mid + 1` 或 `r = mid - 1`，否则可能死循环。

二分复杂度 O(log n)：100 万个数最多 20 次，比线性扫快 5 万倍。

## 3. 二分答案：猜「值」而不是猜「位置」
二分答案的套路更有威力：当答案是某个整数 x，且**x 满足「单调的判定」**——x 可行则更大的也可行（或更小的也可行）——就可以对答案值域二分，每猜一个值用 `check(x)` 判定行不行。

经典场景「求最大化最小值」：把 m 个物品分到若干组，问每组容量至少多大才装得下。容量越大越容易装（判定单调：大容量可行则更大也可行），于是二分容量 x，check 用贪心模拟分组，O(log 值域 × check 代价)。

**口诀：答案能判定，判定有单调，值域来二分。**

> 教学提醒：二分答案的最大误区是 check 写错或单调性不存在。动手前先在纸上问自己一句：「x 可行，比 x 大（或小）的一定可行吗？」答不上来就不能二分。

## 4. 边界与死循环：二分的三大坑
1. `while (l <= r)` 与 `while (l < r)` 配合的更新语句不同，混用导致死循环或漏解。
2. 求「第一个满足条件的位置」时常用模板：

```cpp
while (l < r) {                    // 求最小的可行 x
    int mid = (l + r) / 2;
    if (check(mid)) r = mid;       // mid 可行，答案在左半边（含 mid）
    else l = mid + 1;              // 不可行，去右半边
}
```

3. 值域边界（l、r 的初始值）要按题目数据范围取，如答案在 1~10⁹ 之间，就令 `l = 1, r = 1e9`。

## 6. 课后巩固
1. 概念题：为什么二分查找要求数组有序？给一个反例说明无序时二分可能漏掉目标。
2. 编程题：在升序数组中查找 target，若 target 出现多次，返回**第一次**出现的位置（用 `l<r`、`r=mid` 的模板）。
3. 编程题：读入 n 根长度不一的木条，求把它们每根截成等长小段，每段最长能是多少（使得总段数不少于 k）——用二分答案。
4. 思考题：猜 1~n 的数，二分策略最少几次能保证猜中？用对数解释。
5. 拓展：「二分答案的 check 必须具有单调性」，试举一个单调、一个非单调的判定例子。
