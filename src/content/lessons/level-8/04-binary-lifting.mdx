## 1. 从走台阶说起
「操场有 1000 级台阶，一步只能跨 1 级，要走多少步？」1000 步，太慢了！如果允许你「预存」一些大步子：一次跨 1 级、2 级、4 级、8 级……16 种预设步长（1, 2, 4, …, 512），那么到 1000 级台阶，只需把 1000 拆成二进制：1000 = 512+256+128+64+32+8，**6 步**就到了。

这就是**倍增法（Binary Lifting）**的精髓：**不一步一步走，而是预处理好 2 的幂次大步，任何距离都能拆成若干个 2 的幂之和，大步跳过去。** 任何正整数都能唯一表示成二进制，所以「大步 + 拆分」一定能到达目的地。

## 2. 倍增思想的三要素
竞赛里凡是看到「反复跳很多步」的题，就想想这三板斧：

1. **预处理**：事先算出「一次跳 1 步、2 步、4 步、…、2^k 步」的结果（跳到哪、累计多少）。
2. **二进制拆分**：把目标步数 b 拆成二进制，b 的第 k 位为 1 就用一次 2^k 大步。
3. **逐步合并**：每用一次大步，就把结果合并进答案。

预处理要多少级？2^k 要能覆盖最大步数 N：k = ⌈log₂N⌉。N=10^9 时也只要 30 级——**对数的威力就在这里**。

## 3. 经典应用：快速幂（二进制拆分求幂）
计算 a^b，b 可能高达 10^18，循环乘 b 次绝对超时。把指数 b 二进制拆分：

```cpp
#include <iostream>
using namespace std;

long long qpow(long long a, long long b, long long p) {
    long long r = 1;
    a %= p;
    while (b > 0) {
        if (b & 1) r = r * a % p;   // b 的当前最低位是 1：乘上这一大步
        a = a * a % p;              // 步长翻倍：a, a², a⁴, a⁸…
        b >>= 1;                    // 处理下一位
    }
    return r;
}
int main() {
    cout << qpow(2, 10, 1000000007) << '\n';  // 输出 1024
}
```

循环里 `a = a*a` 让底数平方增长，对应步长 1, 2, 4, 8… 翻倍；`b & 1` 检查当前二进制位是否需要这一步。这正是倍增法的标准形态。

## 4. 时间复杂度分析
倍增法的复杂度要从两头算：

- **预处理**：若每一级都要单独算，共 log N 级，总代价 O(log N)（或 O(N log N)，如树上倍增要预处理每个点的 2^k 级祖先）。
- **单次跳跃**：步数 b 的二进制有 ⌊log₂b⌋+1 位，每步最多用一次大步，所以**单次查询 O(log b)**。

对比「一步一步走」的 O(N)，倍增把指数级的差距拉成了对数。快速幂求 a^b 只要约 60 次乘法（b≤10^18），比一亿次循环快了几千万倍。这是八级大纲明确要求掌握的：**会算倍增法的时间复杂度**。

> 教学提醒：快速幂里务必在每次乘法后立即取模（`a * a % p`、`r * a % p`），并且先 `a %= p`。若 a、b 都接近 10^18，两个 long long 相乘会溢出，要改用 `__int128` 或先取模缩小数值——取模后再乘，数值始终小于 p²，p 不超过 10^9 时是安全的。

## 5. 倍增在竞赛中的身影
快速幂只是起点，进阶应用包括：

1. **树上倍增**：预处理每个点向上 2^k 层的祖先，一次 O(log n) 查询两个点的最近公共祖先（LCA）。
2. **ST 表**：预处理后 O(1) 回答区间最值查询，是 RMQ 问题的经典解法。
3. **二进制拆分优化 DP**：把「选 k 个物品」拆成 log k 个「0/1 选择」，配合单调队列或背包求解。

它们共享同一套心法：**预处理 2 的幂，查询拆二进制。** 口诀：**步长翻倍增，指数拆二进制，复杂度掉成对数级。**
