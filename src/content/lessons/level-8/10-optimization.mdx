## 1. 同样的题，凭什么别人快一千倍？
同样的题目、同样的数据范围，有人 TLE（超时），有人 AC（通过）——差距不在打字速度，而在**是否愿意先想一步：这个算法能不能更好？** 算法优化就是八级大纲的最后一块拼图：理解不同方法在时空复杂度上的差异，用数学和技巧把「能算」变成「算得快」。

优化的起手式永远是三问：**瓶颈在哪？冗余在哪？数学能不能帮我？**

## 2. 优化方向一：用数学公式替代暴力循环
最优雅的优化是「不算而算」——用公式直接求出结果，循环都省了。

经典案例：求 1+2+…+n。循环累加是 O(n)，n=10^9 要跑 10 秒；用**等差数列求和公式** n(n+1)/2，O(1) 直接出答案。这就是八级大纲强调的**使用数学知识辅助求解**：等差数列、等比数列、排列组合公式、方程求解、几何公式……先问自己「这题有没有数学闭式解」，往往比优化代码更划算。

口诀：**能公式不循环，能 O(1) 不 O(n)。**

## 3. 优化方向二：消灭重复计算
程序慢的常见原因是「同一件事算了很多遍」。两大武器：

1. **前缀和**：把「区间求和」的每次 O(n) 查询降为 O(1)。预处理后 sum(l,r)=pre[r]−pre[l−1]。
2. **记忆化**：递归中把已算过的结果存进数组，遇到重复子问题直接查表。斐波那契裸递归 O(2ⁿ)，加记忆化立刻变 O(n)。

它们的本质是**用一次预处理或一块内存，换掉成千上万次重复劳动**。

```cpp
// 前缀和预处理（一次 O(n)）
pre[0] = 0;
for (int i = 1; i <= n; i++) pre[i] = pre[i-1] + a[i];
// 之后每次区间查询都是 O(1)
int sum = pre[r] - pre[l-1];
```

## 4. 优化方向三：空间换时间与剪枝
- **空间换时间**：哈希表用 O(n) 内存换 O(1) 查询；邻接表比邻接矩阵省空间且遍历更快。
- **剪枝**：搜索树上果断砍掉不可能产生答案的分支。经典例子：和为定值的组合枚举中，一旦当前和超过目标立即回溯（最优性剪枝 + 可行性剪枝）。好的剪枝能把 O(2ⁿ) 压到可接受范围。

时空权衡的决策口诀：**内存够就换时间，时间紧就砍分支；两头都不行，回第 2 节找数学。**

> 教学提醒：优化要「对症下药」——先估算瓶颈的复杂度，再决定优化手段。数据范围小（n≤100）时 O(n³) 也能过，盲目上优化反而增加 bug 风险；数据范围大时，先看能否改算法级别（如 O(n²)→O(n log n)），其次才是常数优化。考试中的「算法优化」选择题，绝大多数考的是**复杂度级别的比较**，不是常数微调。

## 5. 课后巩固
1. 概念：列举本课三大优化方向，各找一个课本之外的例子佐证。
2. 计算：用等差数列公式求 1 到 1000 的和，并说明它比循环快在哪。
3. 编程：输入 n 个数与 q 次「单点修改 + 区间求和」操作，思考前缀和还够不够用，若不够请查阅「树状数组」。
4. 思考：搜索问题的剪枝为什么不影响最终结果？什么样的剪枝是安全的？
