## 1. 一秒钟到底能跑多少？
评测机的 CPU 每秒大约能执行 10^8 次基本运算（1 亿次）。这意味着：

- n = 10^5 时，O(n²) 要 10^10 次运算——**跑 100 秒，妥妥超时**；
- 换成 O(n log n)，只要约 1.7×10^6 次——**瞬间跑完**。

复杂度分析就是给你的算法「算预算」：写完代码先估一估运算次数，超预算就换算法，而不是交了题等一个鲜红的 TLE。**先估复杂度、再写代码**，是八级选手与初学者的分水岭。

## 2. 大 O 记号：只看增长趋势
大 O 记号描述的是**当 n 趋于无穷时，运行时间的增长趋势**，常数和低阶项都被忽略：

- 3n² + 100n + 7 → **O(n²)**
- 2ⁿ + n³ → **O(2ⁿ)**

常见复杂度从快到慢的「天梯表」，务必背熟：

| 复杂度 | 名称 | n=10^5 时可否接受 |
| --- | --- | --- |
| O(1) | 常数 | ✅ |
| O(log n) | 对数 | ✅ |
| O(n) | 线性 | ✅ |
| O(n log n) | 线性对数 | ✅ |
| O(n²) | 平方 | ❌（10^10 次） |
| O(2ⁿ) | 指数 | ❌ |
| O(n!) | 阶乘 | ❌ |

经验法则：**1 秒 ≈ 10^8 次运算**。把 n 的上限代入你的复杂度，超过 10^8 就要警惕。

## 3. 给算法「估 Complexity」的三板斧
**第一板斧：数循环层次。** 单层循环 O(n)，双重循环 O(n²)，k 重循环 O(n^k)。例如冒泡排序双重循环 → O(n²)；快速幂中 b 每次减半 → O(log b)。

**第二板斧：看递归分支。** 递归算法用「主定理」直觉估算：二分查找每次规模减半、只有一支递归 → O(log n)；归并排序分成两支、每支 n/2，再线性合并 → O(n log n)；斐波那契裸递归两支展开 → O(2ⁿ) 的爆炸树。

**第三板斧：均摊与常数。** 并查集单次操作近乎 O(1)（反阿克曼函数）；哈希表平均 O(1) 查询。这些「看起来有循环」的结构实际极快，分析时不要误判。

再对照本级别学过的算法复盘一遍：

- **排序**：冒泡/插入 O(n²)；快排/归并 O(n log n)。
- **查找**：顺序查找 O(n)；二分查找 O(log n)。
- **树与图遍历**：DFS/BFS 都是 O(n+m)，每个点访问一次、每条边看一次。
- **搜索（回溯）**：本质是对解空间树做 DFS，复杂度取决于分支数与深度，往往是 O(2ⁿ) 或 O(n!)，要靠剪枝优化。
- **分治**：T(n)=2T(n/2)+O(n) → O(n log n)，如归并排序、最近点对。
- **动态规划**：总代价 = 状态数 × 单个状态的转移代价，如 Floyd 是 n² 个状态各 O(1) 转移 → O(n³)。

## 4. 空间复杂度与时空权衡
**空间复杂度**描述额外内存随 n 的增长：原地排序 O(1)、递归栈 O(log n)~O(n)、邻接矩阵存图 O(n²)、动态规划数组 O(n)~O(n²)。

时空常常可以互换：**用空间换时间**是最经典的优化——前缀和用 O(n) 数组换 O(1) 查询；记忆化搜索用 O(状态数) 数组消灭重复计算。**用时间换空间**也存在，如滚动数组把 O(n²) DP 压成 O(n)。分析题若问「如何优化」，先从这两个方向各想一遍。

> 教学提醒：复杂度分析是选择题高频考点，尤其爱考「给一段代码判断复杂度」和「比较两种算法优劣」。判断代码复杂度时先找最内层语句，再数它被执行的次数随 n 的增长级别；嵌套循环的复杂度是各层相乘，并列结构取**最大项**而非相加。

## 5. 课后巩固
1. 概念：什么是大 O 记号？为什么 3n² + 100n 写作 O(n²) 而不是 O(3n²)？
2. 计算：估算 1 秒、1 分钟、1 小时各能承受的「运算次数预算」，填入 n=10^5 时各预算下可行的最高复杂度。
3. 分析：写出冒泡排序的双重循环，逐层分析它为什么是 O(n²)。
4. 思考：Dijkstra 朴素版是 O(n²)、堆优化是 O((n+m) log n)，试估算 n=m=10^5 时两者运算次数的量级差。
5. 拓展：查阅「主定理」的三个 case，并用它解释为什么二分查找是 O(log n)、归并排序是 O(n log n)。
